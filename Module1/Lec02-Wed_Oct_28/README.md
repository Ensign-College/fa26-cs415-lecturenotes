# Docker Compose

Running one container by hand is fine. Running several with the right settings, every time, is what Docker Compose is for.

Read: [Docker Compose](https://ensign.instructure.com/courses/27288/pages/docker-compose)

## Reading a compose file

Walk through the example line by line:

*   **services**: the containers that make up the app
*   **image**: what each service runs
*   **ports**: how the outside world reaches it
*   **volumes**: data that lives beyond the container
*   **environment**: settings passed in


*Check:* if I delete this container, what survives?
